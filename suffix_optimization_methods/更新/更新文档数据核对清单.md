# 更新文档数据核对清单

写更新文档前，按本清单核对事实和数据。

## 1. 运行目录

记录本次文档涉及的 run：

| 口径 | run 目录 | 用途 |
|---|---|---|
| baseline | `results/invert_timestamp_runs/baseline/<timestamp>` | 原论文或无进阶方法结果 |
| v1.0 | `results/invert_timestamp_runs/suffix_reoptimization_v1.0/<timestamp>` | 旧版本或备份版本结果 |
| v1.1 | `results/invert_timestamp_runs/suffix_reoptimization_v1.1/<timestamp>` | 新版本结果 |

## 2. 必查文件

每个 run 至少检查：

- `resolved_config.json`
- `experiment.log`
- `reconstructions.jsonl`
- 生成的 `.xlsx` 汇总文件，如果存在

## 3. 必查配置

从 `resolved_config.json` 或当前 config 中核对：

- `dataset.actual_len` 或实际 jsonl 行数
- `model.base_model_name`
- `model.num_invert_layers`
- `optimization.epoch`
- `runtime.max_memory`
- `runtime.device_map`
- `advanced_method.name`
- suffix 方法的 enable/log/threshold 参数
- suffix 方法的 `accept_mode`

## 4. 必算指标

从 `reconstructions.jsonl` 计算：

- 每条样本最终 `accuracy`
- 平均 accuracy
- 新版本相对旧版本逐条差值
- 新版本相对旧版本平均差值
- 多少条提升、多少条下降、多少条持平

## 5. 口径提醒

- 单独 baseline run 的最终 `accuracy` 才是“原论文方法最终结果”。
- suffix 方法内部的 `pre_acc` 是进阶方法介入前的当前重构准确率，不等同于单独 baseline run 的最终 accuracy。
- v1.0 / v1.1 同时开启时，当前选择规则优先运行 v1.1。
- 如果运行时条件不同，例如 `max_memory` 或 offload 不同，耗时比较必须标注为非完全公平对比。

## 6. 文档写法提醒

- 数值必须写来源。
- 不确定点必须写“尚需验证”。
- 参考分析可以吸收观点，但要用当前代码和 artifact 校正。
- 小样本结果只能写成“有提升迹象”，不要写成稳定结论。
