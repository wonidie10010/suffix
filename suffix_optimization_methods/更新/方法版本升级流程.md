# 方法版本升级流程

本流程用于 suffix 方法以及后续类似高级方法的版本升级。目标是让新版本可验证、可回退、可对比，而不是直接覆盖旧实现。

## 1. 版本文件

- 在 `suffix_optimization_methods/method_versions/` 中新建下一版本 sidecar 文件。
- v1.2.3 及后续新版本采用完整两阶段 sidecar：Stage 1 初始重构完成后，Stage 2 再做 suffix reoptimization。
- 以当前最高稳定版本为基础复制，再修改类名、入口函数、`METHOD_NAME`、结果字段和版本标记。
- 旧版本文件必须保留，除非用户明确要求删除。

## 2. 独立配置

- 在 `suffix_optimization_methods/configs/` 中为新版本新增独立 config 文件。
- 新参数必须带版本前缀，例如 `suffix_v1_5_0_*`。
- 旧版本 config 不因新版本升级而被改写。

## 3. 显式切换

- 使用总配置中的 selector 选择运行版本。
- 当前 suffix 方法约定为 `suffix_optimization_methods/configs/advanced_methods.json` 中的 `suffix_version`。
- selector 支持明确选择旧版本，方便回退和消融对比。

## 4. 运行接入

- `invert.py` 只做轻量接入：import、config 初始化、版本选择、run 分支、结果记录。
- 方法核心逻辑必须留在版本 sidecar 文件中。
- `reconstructions.jsonl` 中要保留 canonical 版本结果字段；完整两阶段版本按 `stage1` 与 `reoptimization` 分组记录。

## 5. 输出同步

- `experiment_outputs.py` 必须把新版本参数写入 `resolved_config.json`。
- `reconstructions.jsonl` 必须能记录新版本的 `events`、`anomaly_reasons`、`pre_acc` 和 `post_acc`。
- 方法细节及新增结果字段只写入 `reconstructions.jsonl`；除非用户明确要求，固定的 `experiment.log` 摘要不得增加字段、事件或中间状态。

## 6. 测试与验证

- 新增或更新最小单元测试，优先覆盖新增纯函数、版本选择、配置兼容和结果字段。
- 至少运行单元测试和 `py_compile`。
- 如运行条件允许，再做小样本实验，并核对 `resolved_config.json`、`experiment.log` 和 `reconstructions.jsonl`。

## 7. 更新报告

- 每次推出新版本后，在 `suffix_optimization_methods/更新/` 下生成版本更新报告。
- 报告结构必须遵循 `suffix_optimization_methods/更新/更新文档写作模板.md`。
- 若尚未完成完整实验，实验效果部分必须明确写“尚需完整实验验证”。
