# CGMR / Local 方法更新文档写作模板

本模板用于 `CGMR` 方法族中的版本更新、方法改动、实验更新和 Word 更新说明。生成 Word 前先按本模板整理内容；生成后至少做结构检查。

## 1. 标题与资料口径

标题建议：

```text
<方法与版本> 相对 <对照方法或版本> 的关键核心更新
```

开头必须说明参考分析、当前代码/config 和真实实验 artifact 的边界。推测必须标注“尚需验证”或“参考分析推测”。

## 2. 发现了什么问题

- 说明旧候选选择、置信判断或多层评分的具体短板。
- 说明问题如何影响 token 选择、准确率、稳定性或运行开销。
- 若引用实验现象，列出 run 目录和对应 artifact。

## 3. 做了哪些改动

- 按机制描述候选池、低置信度门控、多层聚合、接受条件和前缀更新。
- 写明旧行为、新行为和默认参数。
- 明确 selector、版本开关以及 suffix 与 CGMR 的执行顺序。

## 4. 为什么要做这些改动

- 每项改动对应一个已确认问题。
- 写清预期收益、额外 forward/显存代价和仍需消融的假设。
- 不把多层分数预期收益写成已经验证的效果。

## 5. 改动后的实验效果

本节必须以 `resolved_config.json`、`experiment.log`、`reconstructions.jsonl` 和相关 `.xlsx` 为依据，至少记录：

- baseline、suffix 输出和 CGMR 最终 accuracy 的不同口径；
- 触发位置数、接受替换数、修改位置数和净 accuracy 变化；
- 实际使用层、候选规模、额外耗时；
- 样本级结果和平均值。

若尚未完成实验，明确写“尚需完整实验验证”。

## 6. 后续改进方向

优先写扩大样本、阈值消融、层组合消融、正确位置破坏率、运行时间优化和无 Ground Truth 决策验证。

## 7. Word 交付检查

- 文档包含问题、改动、原因、实验效果、后续方向五个核心章节。
- 文件能被 `python-docx` 打开，实验数值与 artifact 对齐。
- 若 LibreOffice/`soffice` 可用，渲染为 PNG 做视觉 QA；否则注明只完成结构 QA。
