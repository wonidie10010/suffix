# 更新文档写作模板

本模板用于本项目中的版本更新、方法改动、实验更新、Word 更新说明等文档。生成 Word 前，先按本模板整理内容；生成 Word 后，至少做结构检查。

## 1. 标题与资料口径

标题建议：

```text
<版本或方法名> 相对 <对照版本或基线> 的关键核心更新
```

开头必须说明本文资料口径：

- 本文参考了哪些分析、草稿或外部回答。
- 本文以哪些当前代码、config 和实验 artifact 为准。
- 如果参考分析中有不确定或不准确处，需要明确写出“经代码确认后的修正”。

推荐写法：

```text
本文吸收用户提供的参考分析，同时以当前项目代码和实验 artifact 为准进行修正。涉及损失函数、参数和实验结果的描述，均以代码、config、resolved_config.json、experiment.log 和 reconstructions.jsonl 为依据。
```

## 2. 发现了什么问题

这一节回答“为什么需要更新”。要求：

- 先讲原方法或旧版本的核心问题。
- 再讲问题如何影响实验结果、稳定性、速度、可解释性或后续扩展。
- 不要只写抽象评价，尽量落到代码路径、损失函数、配置或 artifact 现象。

建议包含：

- Baseline 或旧版本的优化目标是什么。
- 旧版本在梯度、离散 token 映射、候选重排、接受策略或配置追踪上的短板。
- 如果问题来自实验现象，列出对应 run 目录和关键指标。

## 3. 做了哪些改动

这一节回答“具体改了什么”。要求：

- 按核心机制分组，而不是机械罗列文件。
- 每个改动都写清楚旧版本是什么、新版本是什么。
- 涉及参数时写出默认值。

推荐表格：

| 改动维度 | 旧版本 | 新版本 | 说明 |
|---|---|---|---|
| 位置权重 | 示例：均匀平均 | 示例：front_decay | 示例：异常点附近优先 |
| 正则项 | 示例：强 reg | 示例：弱 prox | 示例：减少过度回拉 |
| 先验约束 | 示例：无词表最近邻 | 示例：manifold loss | 示例：锚定词表流形 |

## 4. 为什么要做这些改动

这一节回答“改动背后的理由”。要求：

- 每个核心改动都要对应一个问题。
- 写清楚预期收益和可能代价。
- 对推测性收益要谨慎表述，例如“预期”“有助于”“需要消融验证”。

推荐结构：

1. 改动 A 解决问题 X，因为……
2. 改动 B 解决问题 Y，因为……
3. 改动 C 带来收益 Z，但可能增加……

## 5. 改动后的实验效果

这一节必须 artifact-backed。要求：

- 列出样本级结果表。
- 列出平均值。
- 写明使用的 run 目录、数据集长度、关键配置和评估口径。
- 如果样本数较少，要明确说明结论只是初步迹象。

推荐表格：

| 样本 | Baseline | v1.0 | v1.1 | v1.1 - v1.0 |
|---|---:|---:|---:|---:|
| 样本 1 |  |  |  |  |
| 平均 |  |  |  |  |

结论推荐写法：

```text
在当前 <N> 条样本实验中，<新版本> 平均 accuracy 为 <value>，相对 <旧版本> 平均提升 <delta>。由于样本数仍然较小，当前结论应表述为“有正向提升迹象”，仍需更大样本和多随机种子验证稳定性。
```

## 6. 后续改进方向

这一节回答“下一步怎么做”。要求：

- 写可执行方向，不写泛泛口号。
- 优先包含：扩大样本、消融实验、运行时间优化、公平对比、无 oracle 策略验证。
- 如果新增了配置项，要说明后续怎么用它做对比。

推荐方向：

1. 扩大 dataset_len，并加入多随机种子。
2. 做关键权重或模块消融。
3. 对比不同 accept mode 或触发策略。
4. 优化耗时热点。
5. 在相同运行时条件下做公平对比。

## 7. 必须避免的问题

- 不要把其他模型回答中的推测直接写成事实。
- 不要把单独 baseline run 的最终 accuracy 和 suffix 内部 `pre_acc` 混淆。
- 不要只根据历史 run 名称判断方法是否开启；必须检查 `resolved_config.json`。
- 不要遗漏样本级结果表。
- 不要只写“效果更好”，必须给出数值、平均值和限制条件。

## 8. Word 交付检查

生成 `.docx` 后至少检查：

- 文件能被 `python-docx` 打开。
- 文档包含五个核心章节：问题、改动、原因、效果、后续方向。
- 表格中所有实验数值与 `reconstructions.jsonl` 对齐。
- 若 LibreOffice/`soffice` 可用，渲染为 PNG 做视觉 QA。
- 若无法渲染，最终回复中说明“已完成结构 QA，未完成视觉渲染 QA”。
