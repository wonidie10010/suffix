# CGMR 方法版本升级流程

本流程用于 Confidence-Gated Multi-Layer Reranking（CGMR）及后续 token 候选后处理版本。

## 1. 版本文件

- 在 `CGMR/method_versions/` 中新建下一版本 sidecar。
- 以当前稳定版本为基础修改类名、入口、`METHOD_NAME` 和结果字段。
- 保留所有旧版本，除非用户明确要求删除。

## 2. 独立配置与 selector

- 每个版本在 `CGMR/configs/` 中有独立 JSON config。
- 参数使用 `cgmr_vX_Y_*` 前缀。
- `CGMR/configs/candidate_reranking_methods.json` 中的 `cgmr_version` 显式选择版本，并支持回退到旧版本或 `none`。

## 3. 运行接入

- 完整 suffix 或冻结 baseline 上游方法先完成，CGMR 后处理再运行。
- `invert.py` 只保留轻量 orchestration；候选构建、多层评分、置信门控和接受逻辑放在 sidecar。
- `reconstructions.jsonl` 同时保留版本专属结果和统一 `candidate_reranking_result`。

## 4. 输出同步

- `experiment_outputs.py` 写入 selector、版本参数和实际有效层。
- JSON 中分开记录 suffix 与 CGMR 的结果，避免混用口径。
- 方法细节及新增结果字段只写入 `reconstructions.jsonl`；除非用户明确要求，固定的 `experiment.log` 摘要不得增加字段、事件或中间状态。

## 5. 测试、实验与更新报告

- 测试覆盖版本选择、配置校验、层边界、评分聚合、置信触发、保守替换和无 Ground Truth 决策。
- 实验核对 `resolved_config.json`、`experiment.log` 和 `reconstructions.jsonl`。
- 更新 Word 写入 `CGMR/更新/`，并遵循本目录的写作模板和数据核对清单。
- 尚未完成完整实验时，实验效果部分必须写“尚需完整实验验证”。
