# DEML 默认实验执行流程

本文件是本项目实验执行约定的单一事实来源。用户要求“进行实验”“实验验证”“跑实验”“验证这版效果”等实际实验操作时，默认授权连续完成：

**更新 GitHub → 同步服务器项目 → 检查实验条件 → 启动实验 → 持续监测 → 结果回传与校验。**

## 范围与弹性

- 版本、对照组、模型、数据、样本量、随机种子、预算和评估口径，按本次上下文、已确认方案及对应配置确定。流程固定，实验设计按任务决定。
- 用户可指定“只检查条件”“仅 dry-run / smoke-test”“只在本地验证”“不推送”“只监测现有实验”等范围；当次指令覆盖默认步骤。
- “继续实验”“收尾”从当前状态接续，复用已经通过且仍适用的检查。发现同一实验正在运行时直接监测它。
- 常规实现选择、环境修复和步骤衔接自行处理；涉及无法合理推断的关键实验选择、扩大资源预算或缺少必要权限时，再询问或说明阻塞。
- 流程完成点是结果已回传、校验并汇报。关机按用户另行指定的机器和时机执行。

## 1. 更新 GitHub

核对本次方法和配置已落实，完成与改动风险相符的必要检查。查看 Git 状态，仅提交本次实验需要的代码、配置及文档，保留用户原有改动。沿用项目已配置的 remote 和目标分支；没有新改动时核对已有提交即可。

**完成条件：**实验所需提交已在 GitHub，记录其 commit；需要的本地检查已通过。

## 2. 同步服务器项目

默认沿用现有 SSH 配置中的 `server-3090-vscode` 和服务器项目 `/mnt/my_disk/tch/suffix`；用户指定其他目标时使用指定目标。Windows 连接时显式传入现有 `%USERPROFILE%\.ssh\config`。

先查看服务器工作区，再以快进更新或其他保留现有改动的方式同步。保留服务器的数据、环境、缓存和历史结果；遇到影响实验的差异，先处理该差异。GitHub 连接暂时失败可重试；必要时使用可校验的 Git bundle 同步已推送的同一提交。

**完成条件：**服务器实际源码与计划实验的 commit 对应，工作区中影响本次运行的差异已明确。

## 3. 检查实验条件

使用本次方法对应的现有入口和配置，核对：

- 实际 selector、方法开关、关键参数、评估口径与实验方案。
- 数据文件可读且样本范围正确；配对实验的样本顺序、初始快照和其他控制条件符合本次约定。
- 解释器、依赖和模型可用；复用现有模型缓存，并固定实际模型路径。
- GPU、显存、磁盘及现有进程允许启动本次实验。

按风险执行必要的测试、dry-run 或最小 smoke-test；同一代码与环境下已通过的检查可复用。修复导致代码变化时，更新 GitHub 和服务器后再检查受影响部分。

**完成条件：**没有影响正式运行的未解决问题；实际配置、commit、模型、设备和数据范围能够从运行记录追溯。

## 4. 启动实验

通过对应入口启动，使用当前实验独立的 run ID、结果目录和后台会话。沿用入口自带的运行锁与输出方式，记录启动命令、会话或 PID、日志和 artifact 路径。启动后确认进程存活，且日志或阶段产物已经开始产生。

**完成条件：**正式实验确实开始运行，其身份与结果路径清晰，并已安排可持续执行的监测和完成后的回传。

## 5. 持续监测

检查本次 run 的状态记录、日志、逐样本结果数量、进程和 GPU；结合预期进度判断正常运行、完成或异常。通常每 15 分钟检查一次，可按耗时和异常风险调整。运行正常且没有新情况时保持安静；完成、失败或需要用户操作时通知。

长实验使用可持续运行的后台会话及当前聊天的监测安排。若采用定时心跳，其提示词绑定本次 run 和准确路径：读取状态，完成后一次性回传指定产物并校验，随后停用本次监测。代码修改、推送和重启等修复在当前已授权任务中按具体问题处理，避免加入每次定时检查的常规动作。

遇到自动审批或执行权限限制时，遵守工具返回的限制；可保留只读监测，并明确尚未完成的回传或其他步骤。只读状态检查不能替代整个实验任务的完成。

**完成条件：**根据状态记录和实际 artifact 确认成功完成；或确认失败，保留产物并查明需要处理的问题。失败时按问题恢复，保留失败 run；成功时直接进入回传，无需用户再次发出“收尾”。

## 6. 结果回传与校验

将正式结果回传到本地 `实验/结果/` 下按方法和 run ID 区分的目录，或用户指定位置。至少保存每组的 `resolved_config.json`、`experiment.log`、`reconstructions.jsonl`；配对实验同时保存 manifest、comparison、共享快照及对应运行目录。失败实验也保留已有配置、日志和诊断产物。

核对关键文件 SHA256、样本数、组间配对关系及必要的快照一致性；从实际 artifact 核对最终指标。沿用 AGENTS.md 的日志、评估和文档口径，结果产物保存在本地实验目录。

回传校验完成后，停用本次创建或复用的监测，清理本任务临时文件，并简洁汇报本地结果位置、实际实验条件、主要结果与剩余问题。若更新了已有结果报告，再核对该报告；需要同步的报告按第 1、2 步更新。

**完成条件：**产物已在本地可读且与服务器一致，结果已核对并汇报，本次监测及临时工作已收尾。若步骤受阻，明确记录已完成部分和待处理项，保持实验任务未完成状态。
