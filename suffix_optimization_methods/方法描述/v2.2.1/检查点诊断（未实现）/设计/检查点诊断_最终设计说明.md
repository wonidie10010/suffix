## 1. 方法目标与决策合同

在左到右 token 恢复过程中，每完成一个固定的 5-token 离散段，利用当前段和目标段的 hidden 和向量做一次审查。仅在段级 cosine 低于 0.90 时，展开累计轨迹，定位一个待处理位置，再用原候选池中的合格候选做单点替换试算。

方法希望增加的是：对已经作出的局部选择，利用段内后续位置的实际 hidden 表现进行再次评价。它不证明异常点就是错误源，也不证明 hidden 改善意味着真实 token 恢复正确。

| 已冻结事项 | 本版合同 |
| --- | --- |
| 分段 | 固定前缀之后开始，5 个 token 一段，严格不重叠 |
| 尾段 | 不足 5 个 token 不做 checkpoint |
| 触发 | 原始 hidden 向量直接求和，整组 cosine 严格小于 0.90 才触发 |
| 诊断 | 段内累计 cosine 与相邻变化，区分孤立异常和累计恶化 |
| 累计恶化定位 | earliest sustained drop，不回溯到更早 token |
| 处理范围 | 一个位置，固定其余离散 token ID |
| 候选 | 复用该位置已有候选表；便宜筛选后，逐候选重新前向下游 |
| 排序与接受 | 按新段级 cosine 最大值选优；只要严格优于旧段级 cosine 就提交 |
| 次数 | 每个 checkpoint 最多一次修复；不二次诊断、不递归修复 |
| 后续 | 使用修复后的已提交前缀，继续尚未提交的位置 |
| 在线输入 | 目标 hidden 可以使用；GT token、accuracy、oracle correctness 不得参与决策 |

段级指标不是逐位置 cosine 的均值，也不是 R 的 front-decay hidden loss。不先逐 token 单位化，不对 hidden 做中心化，不增加偏差抵消检测、相对 MSE 或第二个接受门控。

### 2.1 必须显式处理的三处接口差异

1. **提交时机缺口**：当前没有 5-token checkpoint 调度器，需要在新版本中增加单调前进的提交游标，并统一所有 R 分支的收尾位置。

## 3. Hidden 来源、层与位置协议

### 3.1 两边必须是同一坐标系

目标侧现有路径：`get_hidden_state(..., up_to=False)` 对 `model.layers.<L>` 注册 hook，主流程取 `all_hidden_states[-1]`，传给 sidecar 的 `target_hidden_state`。当前离散侧 helper 则取同一 hook 收集列表的 `[0]`。

这里 `L=args.num_invert_layers` 实际是 **从 0 开始的 Transformer block 索引**。示例值 24 意味着 hook `layers.24`，不能按名字解释为“前 24 层”或直接写作 `hidden_states[24]`。若另用 Hugging Face hidden collection，必须先对照 exact block output 验证，尤其注意 collection 的输入 embedding 项、最终归一化位置和 tuple 附加输出。

**工程选择**：新版本统一使用 exact-layer 提取：若 block 返回 tuple，只取 `output[0]`；否则取 tensor 本身。目标获取留在主流程或独立采集层，checkpoint 只接收结果 tensor。新分支不能继续靠“列表最后一项一定是 hidden”假设；目标与当前都检查 `[1,T,D]`、同一 block ID、相同位置排列。可参考 `CGMR_v1_0.py:88–134` 的 exact-layer 提取方式，但不引入 CGMR 评分或门控。

本版限定同一 Qwen2/Qwen2.5 causal LM、同一权重/adapter 状态、相同 tokenizer 和输入位置协议。缓存目标若来自另一 adapter 状态，不属于本次冻结合同，必须显式拒绝或在后续研究中单列，不能与同模型目标混用。目标采集用真实输入是目标观测构造；把其 token ID 继续传入在线修复器则是越界。

### 3.2 绝对位置与恢复位置

设完整序列长度为 `T`，固定公开前缀长度为 `E=eval_start_pos`。统一使用 Python 的 0-based 绝对 token 位置：

- 固定前缀：`[0,E)`；待恢复位置：`[E,T)`。
- 第 `g` 个完整 checkpoint（`g` 从 0 开始）：`a=E+5g`，`b=a+4`，仅在 `b<T` 时存在。
- hidden 切片：`[:,a:b+1,:]`；位置 `p` 对应 `target[:,p,:]`，没有 next-token 的 `+1/-1` 偏移。
- 段内位置：`p-a`；面向读者的恢复序号：`p-E+1`。日志同时明确索引基准，不混写。

例如 `E=1` 时，第一段绝对索引为 `[1,5]`，对应第 1–5 个待恢复 token；第二段 `[6,10]`。`E=0` 时第一段 `[0,4]`。完整段数是 `floor((T-E)/5)`。

现有 v2.2.1 只在输入首项已经是 special token 时令 `E=1`，否则 `E=0`；`ensure_suffix_v2_committed_prefix` 的自动插入集合不含 v2.2.1。本版不借新名称自动插入 EOS/BOS，也不沿用其他版本不同的前缀变换。

固定前缀必须是攻击设置中公开、预先给定的前缀（如 tokenizer 的固定 BOS）；不能借“fixed_prefix_tokens”传入未知目标普通 token。新版本前置检查必须区分公开前缀元数据和离线 GT；E 的建立不能把任意目标首词泄漏给方法。

本版先支持 batch=1、全有效且未填充的输入 token 区域，与当前逐样本主流程一致。新版本显式拒绝混合长度 padding/内部 mask 空洞，避免按张量长度把 padding 算进段；扩展 batching 不属于本轮。

## 4. Checkpoint 在 v2.2.1 流程中的位置

### 4.1 提交边界的定义

保留 Stage-1、初始完整 rerank、原 R 优化与原 R 接受规则。增加 `committed_end`：表示最右侧已完成该位置 R 处理、且已确认当前上下文的离散 token 位置，初值 `E-1`。

完整初始 rerank 和 R 内部 suffix rerank 对未来位置产生的是**暂定结果**。它们可以保留以复用原流程，但不推进 checkpoint 游标，不建立 checkpoint，不消耗修复次数。

外层位置 `i` 的顺序为：

1. 若未来候选因上一个 checkpoint 修复而失效，用原候选策略在当前前缀下更新位置 `i` 的暂定 token 与候选表。
2. 执行原 v2.2.1 在 `i` 的 R 触发、预算检查、试算及接受/拒绝。R 的预算和损失合同保持原样。
3. 无论 R 未触发、预算耗尽、接受、拒绝或可恢复的 trial 失败，都到达同一个位置收尾点：确认位置 `i` 的 token 与有效候选表，令 `committed_end=i`。
4. 若 `(i-E+1)%5==0`，对刚完成的 `[i-4,i]` 执行一次 checkpoint；否则进入 `i+1`。

当前代码的 `continue` 分支必须在新 sidecar 中改为统一收尾，不能因 R 预算已耗尽而跳过 checkpoint。checkpoint 不占用 R 的“两次样本 attempt”预算；自己的上限由完整段数和每段一次修复保证。

### 4.2 为什么不直接在原 rerank 循环里插入

一次 R 候选尚未被接受时，内部 rerank 可能已经走到序列末尾。若在这里修复，会把试算当成正式提交，且同一段可能被重复访问。相反，等整个 suffix 方法返回后再做 checkpoint，又无法让中间修复影响正常的后续恢复。因此插入点必须是外层单调位置收尾，而非嵌套候选循环或最终输出后处理。

这一安排是为匹配 live code 增加的调度设计，不把 v2.2.1 改造成另一套全局搜索，也不执行其 `2重优化/待做.md`。

## 5. 第一层：整段审查

在边界 `b`，从**当前已提交的离散 ID 前缀 `tokens[:b+1]`** 得到目标 block 的 hidden。不能使用 `current_embedding` 的连续尾部前向结果，也不能把五个不同历史时刻的缓存 hidden 拼成一个段。

对 `S=[a,b]`：

```text
H_old = sum(h_i, i=a..b)
H_target = sum(h_i_target, i=a..b)
C_old = cosine(H_old, H_target)
```

- `C_old >= 0.90`：结束本 checkpoint。
- `C_old < 0.90`：进入累计诊断。

**数值工程选择**：hidden 转 FP32 后求和及 cosine；旧值与全部候选使用同一计算方式。非有限值或和向量范数不大于 `1e-8` 时，cosine 标记为不可用，保留原状态并结束本段，记录数值失败。此检查只定义 cosine 的数值有效域，不作为防抵消指标；对仍有有限方向的抵消情况不加第二道 gate。

禁止把不可用值填成 0 来强制触发，也不四舍五入后比较 0.90。`1e-8` 是工程数值保护常数，不是接受 improvement margin。

## 6. 第二层：累计诊断与唯一定位

触发后，在同一组五个 hidden 上计算：

```text
C[k] = cosine(sum(h_i, i=a..k), sum(h_i_target, i=a..k))
Delta[k] = C[k] - C[k-1], k=a+1..b
```

始终满足 `C[b]=C_old`。`C[a]` 有值，但没有段内前一步，`Delta[a]=null`；不人为引入 `C[a-1]=1`，不读取上一 checkpoint 来制造下降起点。

### 6.1 未冻结容忍量的最小参数化

正式说明未冻结“明显下降”和“基本恢复”。**待实验定标项**采用一个解释清楚的参数 `eta`，同时表示有意义下降的最低幅度和恢复容忍量：

- 明显下降：`Delta[k] < -eta`。
- 恢复到下降前水平：`C[j] >= C[k-1]-eta`。

建议首轮工程种子为 `eta=0.01`，不是已有统计结论，也不是上位说明冻结的常数。后续实现必须把实际值落入 resolved config；正式比较前固定，不能按测试 GT/accuracy 动态调整。只用这一容忍参数，避免另加传播打分器或阈值模块。若后续开发集表明这一共用规则不合理，需要显式修订设计，而不是在测试中自动适应。

### 6.2 可执行的两类定义

针对每个明显下降点 `k`，以其下降前水平 `B=C[k-1]` 为基准，观察本段剩余位置：

| 条件 | 分类与定位用途 |
| --- | --- |
| 在 `k+1` 或 `k+2`（不越过 b）首次达到 `B-eta` | 孤立异常候选，处理位置仍为 k；后面若又下降，作为另一个下降事件独立判断 |
| 至少有一个后续位置，且从 `k+1` 至 b 均低于 `B-eta` | 累计恶化候选，说明在本段可见范围内持续未恢复 |
| 第 3 个或更晚后续位置才恢复 | 不强归入上述两类，记为恢复过晚、证据不足 |
| `k=b`，没有后续观察 | 右端证据不足，不因没有恢复样本而自动判为持续恶化 |

只需要至少一个后续位置才能构成“持续”是第一版工程选择，因此倒数第二位置最多只有一个后效样本，证据较弱，必须记录 `followup_count`。不跨段借位置，不延长 checkpoint，也不增加第三种可修复异常类型；“证据不足”是没有足够定位依据的退出状态。

### 6.3 唯一位置的确定顺序

1. 若有累计恶化候选，取其中绝对位置最小的 k，即 earliest sustained drop，优先于此前已恢复的孤立波动。
2. 否则若有孤立异常候选，取下降幅度最大的那个；幅度并列取位置更早者。这是解决多处孤立异常的确定性工程选择。
3. 否则 `p=null`，结束 checkpoint，不用最小单点 cosine、段首或段末补一个位置。

如果整段一开始就很低、但没有明显下降，或者缓慢下降的每一步均未超过 eta，本版可能触发而无法定位。段首缺少段内前一步，也无法直接成为下降点。这些都是显式局限，不通过新增 baseline、回溯或强行修复规避。

以下是按 `eta=0.01` 手工构造的规则说明，不是实验轨迹：

| 五点轨迹 | 解释 |
| --- | --- |
| 0.96, 0.89, 0.95, 0.85, 0.84 | 第一处下降已恢复；选择第四点的最早持续未恢复下降 |
| 0.88, 0.80, 0.88, 0.88, 0.87 | 第二点孤立下降后恢复，整段仍低于 0.90，选择第二点 |
| 0.98, 0.97, 0.96, 0.95, 0.80 | 末点下降没有后效样本，其他变化不超过容忍量时不定位 |
| 0.85, 0.85, 0.85, 0.85, 0.85 | 已触发但没有下降事件，不修复 |

以上小数用于说明概念；实际比较使用未舍入值，临界值边界用构造精确输入验证。

## 7. 候选表复用与便宜筛选

### 7.1 复用哪一张表

只使用定位位置 p 在**当前被接受的运行状态**下的有效候选表。它可能来自初始 rerank，也可能来自某次已接受的 R suffix rerank，或修复前缀后正常继续恢复时的当前位置刷新。

运行时维护 `candidate_table_by_position[p]`，包含原候选顺序、重复项、单点 cosine、所选 ID、前缀 `tokens[:p]` 的指纹以及产生该表的状态代次。R 拒绝时连同试算表一起丢弃；不能从 JSONL 反读表，也不能凭最后一个 event 推断其有效。

在因果模型下，p 后面的 ID 改变不会改变单点 h_p，因此前缀一致时旧单点评分仍可用于便宜筛选；但它绝不能替代候选在当前固定下游下的新段级评分。前缀指纹不一致属于表失效，正常恢复阶段应刷新；checkpoint 入口仍失配则结束并报明确原因，不私自生成新候选池。

### 7.2 实际候选规则与阈值缺口

原候选顺序固定为 embedding Top-K，再追加 PPL Top-K（仅 `p>0` 且开启 perplexity 时）。不引入旧版本候选源、CGMR 候选或新的 LM 搜索。PPL helper 名字虽叫 perplexity，实际在这里利用 next-token 概率 Top-K。

本版筛选顺序：

1. 读取有效旧表，保留原顺序。
2. 对拟替换项做 ID 范围、special token 和 `filter_nonascii` 对应的确定性合法性检查。此处是新 checkpoint 的明确工程补齐，不能倒称旧池已净化；不修改原 rerank 的旧行为。
3. 复用表中已有 `candidate_hidden_cosine >= candidate_min_cosine` 的项；非有限分数淘汰。
4. 当前 token 作为原结果参照，不必重复前向，也不需要满足候选下限；保留原 token 的权利不受筛选影响。
5. 重复 ID 可按首次出现顺序仅前向一次，记录原始行到唯一 ID 的映射。这是计算复用，不改变候选集合或并列优先级。

`candidate_min_cosine` 是**待确定的新增工程配置**，范围 `[-1,1]`，没有隐式默认值。当前 repo 没有可以诚实复用的数值；正式运行配置未给出时前置校验失败。不得用当前所选项的分数作为自动下限，否则原单点 argmax 通常会把其他候选全部排除。不得把 Top-K 个数描述成 cosine 阈值。

无合格替代候选时结束当前 checkpoint，不转而处理第二个位置，也不放宽阈值。候选数量自然受原池限制；示例 K=10+10 时至多 20 行，不另加方法性 Top-N 截断。

## 8. 候选重新前向与比较

锁定旧段快照、旧 `C_old`、位置 p 和其他 token ID。每个合格候选 v 独立构造 `tokens^(v)`，只有 p 改变，所有候选都从同一旧状态出发，不把前一个候选作为下一个起点。

```text
新段和 = sum(旧 h_i, i=a..p-1)
        + sum(重新前向 h_i^(v), i=p..b)
C_candidate[v] = cosine(新段和, H_target)
```

p 之前的 hidden 只能在因果前缀完全一致时复用；p 至 b 必须重新计算。p+1 至 b 的 token ID 固定，但它们的 hidden 会随 p 改变。无需把 b 之后的未提交位置纳入段级评分，也不能把连续 embedding 与离散 hidden 混用。

### 8.1 缓存执行合同

主实现方案新增前缀 KV 适配器：先对 `[0,p)` 建立只读基础缓存，再用 `[p,b]` 的固定 ID 片段（每候选只改首项）继续前向；目标 block hook 只截取该片段的 hidden。缓存必须来自当前离散前缀、同一模型状态，不能来自目标序列或连续 embedding。

- `p=0` 时无需基础缓存。
- 每候选使用独立缓存副本，避免可变 cache 原地追加污染其他候选；默认顺序评估，不要求批量 cache 扩张接口。
- 传入完整前缀加片段所需的 attention mask，以及与绝对位置 p 对齐的位置元数据。RoPE/cache position 细节需按真正安装的模型实现适配，不能仅按 requirements 文件假定接口已验证。
- 当前 helper 无此能力，必须新增；基础缓存只为本次试算使用，checkpoint 结束即丢弃。
- 在缓存验证路径中，用相同离散 `tokens[:b+1]` 做完整前缀前向对照。若运行环境不支持缓存，只允许显式配置 `full_prefix` 模式，不允许异常后静默切换；该模式保持语义但每候选从起点到 b 重算，开销更高，须如实记录。
- 已选择 cached 模式后发生缓存接口错误，当前段保留原状态并记录失败；不返回伪造分数。

旧段和候选的评分尽量使用同一前向路径，避免批量方式或缓存路径不同造成极小分数差被严格大于接受规则放大。基础旧值已经由同一确定性适配器取得时可复用；不靠增设接受 epsilon 解决数值问题。

## 9. 接受、保留与后续恢复

在有限、有效的候选评分中取 `argmax C_candidate`；完全并列按原候选表首次出现顺序取值。严格使用：

```text
best_score > C_old  → 提交唯一 token 替换
否则                → 保留旧状态
```

不要求 best_score 达到 0.90，不加 improvement margin，不附加 R hidden loss、单点不恶化或下游逐点全部改善条件。其他位置 hidden 是否一致改善可用于离线解释，但不是本版 gate。

接受时更新 `current_tokens[p]`、对应恢复文本和已提交离散前缀；为保持后续锚定输入一致，新版工作 embedding 在 p 处同步为所选 token 的真实 embedding。除 p 外不改 token ID，不把 checkpoint 变成连续优化；p+1..b 的 ID 保持固定。

所有旧缓存与受影响候选表显式失效。后续 `i=b+1` 的 R 锚定前缀必须来自修复后的 token ID，而不是修复前 continuous embedding 切片。对于旧全序列 rerank 已生成的未来暂定结果：在它们首次正式提交前，按原 embedding Top-K + PPL Top-K + 单点 scorer 在新前缀下刷新；这只处理尚未提交的位置，不重跑已完成段。

若以后某次 R 被接受，它产生的新有效候选表可覆盖其后缀暂定表；若 R 被拒绝，只保留进入该 R 前的状态，不能撤销此前已提交的 checkpoint 修复。

拒绝或数值失败时，tokens、工作 embedding、正式游标前缀和有效表保持旧值；试算临时状态丢弃。一个 checkpoint 结束后不论是否触发、定位、接受，均标为完成，不再因指标仍低而返回。继续下一个不重叠段；尾段按原恢复流程完成。

## 11. 限度与必须由实验回答的问题

1. 原始 hidden 和向量方向是否比逐点 cosine 均值/最小值增加可用信息；共同方向、向量尺度或误差抵消是否让段分数失真。
2. 5-token 不重叠、尾段跳过、段首无相邻下降证据、末点无后效证据各漏掉多少可修复情况。
3. 固定 0.90 的触发覆盖率、误触发率与计算成本；本版不在测试时修改它。
4. eta 工程种子、孤立异常优先规则、最少一个后效位置是否稳定；有多少触发段无法定位。
5. 候选下限如何在独立开发数据上预先确定；保留多少候选、是否过滤掉能够改善段级结果的候选。
6. earliest sustained drop 是否比最大下降点更有干预价值；只能研究相关性和受控替换效果，不能宣称它必然是真实错误源。
7. 单点替换固定段内其他 ID 的局限，以及 hidden 改善但 token accuracy 下降的补偿案例比例。
8. 严格大于接受是否频繁选中只有数值噪声级收益的候选；不能在本版私加 margin。
9. 缓存与完整前向的一致性、实际 forward 次数/处理 token 数/时间/显存，以及继续恢复时刷新的额外开销。
