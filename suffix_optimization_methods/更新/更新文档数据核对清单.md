# 更新文档数据核对清单

本清单是 suffix 更新文档实验 artifact、配置和指标核对的单一事实来源。写更新文档前必须完成本清单；文档结构和措辞要求由 `suffix_optimization_methods/更新/更新文档写作模板.md` 规定。

## 1. 运行目录

记录本次文档涉及的 run：

| 口径 | run 目录 | 用途 |
|---|---|---|
| baseline | `results/invert_timestamp_runs/baseline/<timestamp>` | 原论文或无进阶方法结果 |
| 对照版本 | `results/invert_timestamp_runs/<old_method_version>/<timestamp>` | 直接对照版本结果 |
| 新版本 | `results/invert_timestamp_runs/<new_method_version>/<timestamp>` | 本次更新版本结果 |

## 2. 必查文件

每个 run 至少检查：

- `resolved_config.json`
- `experiment.log`
- `reconstructions.jsonl`

## 3. 必查配置

从 `resolved_config.json` 或当前 config 中核对：

- `dataset.actual_len` 或实际 jsonl 行数
- `model.base_model_name`
- `model.num_invert_layers`
- `optimization.epoch`
- `runtime.max_memory`
- `runtime.device_map`
- `advanced_method.name`
- suffix 方法的 enable/log/threshold 参数
- suffix 方法的 `accept_mode`

## 4. 必算指标

从 `reconstructions.jsonl` 计算：

- 每条样本最终 `accuracy`
- 平均 accuracy
- 新版本相对旧版本逐条差值
- 新版本相对旧版本平均差值
- 多少条提升、多少条下降、多少条持平

## 5. 口径提醒

- 单独 baseline run 的最终 `accuracy` 才是“原论文方法最终结果”。
- suffix 方法内部的 `pre_acc` 是进阶方法介入前的当前重构准确率，不等同于单独 baseline run 的最终 accuracy。
- 方法版本和 enable 状态必须从 `resolved_config.json` 中的实际 selector 与配置确认，不能根据 run 目录名推断。
- 如果运行时条件不同，例如 `max_memory` 或 offload 不同，耗时比较必须标注为非完全公平对比。
