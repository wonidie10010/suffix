## 2. 现有调用链与接入位置

当前运行链路：

```text
实验/一键运行_suffix_v2_2_1.py
  → 实验/环境和实验/内部文件/runner_suffix_v2_2_1.py
  → invert.py：config include / selector / 目标 hidden / Stage-1
  → run_suffix_reoptimization_v2_2_1
      → 初始 _rerank_positions（完整未来暂定序列）
      → 外层 for position
          → 锚定前缀 → R trigger / budget
          → _optimize_suffix → _rerank_positions（试算后缀）
          → R hidden-loss 接受或保留
      → 返回 final_tokens / embedding / events
  → 主流程选择返回 token → 可选 CGMR → JSONL / 固定日志摘要
```

新 checkpoint 位于**外层每个位置统一收尾处**。原 `continue` 分支必须在新版本中改为统一收尾；R 的内层 rerank 禁止触发 checkpoint。未触发或耗尽 R 预算时，仍按提交位置计数，每五个执行 checkpoint。

### 3.1 Stage-1 与版本隔离

live v2.2.1 的 Stage-1 目前在 `invert.py`，不能把旧历史流程中的“完整两阶段 sidecar”当成已经完成的重构。推荐新版本提供一个完整两阶段入口：将当前实际使用的 legacy Stage-1 路径按行为复制到新 sidecar 的 Stage-1 函数，再调用基于 v2.2.1 的 R + checkpoint 阶段；旧版本继续走原分支。

这一搬迁只服务新版本入口，必须用相同初始化 embedding、随机状态和优化参数做 Stage-1 等价测试；不能顺手换成另一个 baseline helper，因为梯度目标、初始化、裁剪、步数及候选阶段未必完全等价。不要把 `2重优化/待做.md` 的 trigger 或 prox 变更夹带进来。

新版内部另设一个接收 Stage-1 输出的第二阶段入口，便于在同一 Stage-1 快照下比较 CP off/on。若届时 live 升级规范允许继续外置 Stage-1，可保持旧调用形式；这只是入口包装选择，不能改变 checkpoint 时机、R 合同或候选来源，须在实施记录说明最终采用的入口形式。

## 4. 新版最小模块职责与接口草案

下列名字是拟新增接口，不是已存在函数。将它们组织在一个版本 sidecar 内即可，无需新建复杂框架。

| 职责 | 输入 | 输出/副作用边界 |
| --- | --- | --- |
| `validate_checkpoint_contract` | 配置、目标 hidden 元数据、模型/位置/公开前缀信息 | 检查 5/0.90/次数固定合同，验证候选阈值、目标层、形状、mask；不得接收 GT |
| `finish_position` | 游标、当前 token、已接受 R 状态及候选表 | 推进一个位置；每到完整段末执行一次 checkpoint；所有 R 分支必须到达 |
| `build_segment_observation` | tokens[:b+1]、目标 [a:b+1] hidden、目标层 | 当前离散段 hidden、原始和向量、C_old；不可用返回明确状态 |
| `diagnose_segment` | 五点累计 cosine、eta | p 或 null、类型、逐步变化、下降前水平、恢复位置、后效数量、原因 |
| `filter_existing_candidates` | p 的有效旧表、公开合法性规则、候选 cosine 下限 | 按原顺序的合格唯一 ID 及排除原因；不调用生成器 |
| `forward_candidate_segment` | 当前离散前缀、固定段内 ID、p、候选 ID、缓存上下文 | 新 p..b hidden；不修改正式 token / 基础 cache |
| `evaluate_checkpoint_candidates` | 同一旧快照、所有合格候选 | 每候选 C、最佳候选、有限值状态；每次试算都从旧快照开始 |
| `commit_checkpoint_result` | 最佳值与旧值、正式状态 | 仅 strict > 时更新一个 ID 与其工作 embedding；结束 checkpoint，不递归 |

公共在线入口不得包含 `total_input_ids`、`target_token_ids`、`accuracy`、`oracle` 参数，也不得接受带这些信息的闭包或整条离线 record。目标输入只包含 detached hidden tensor 及非 GT 元数据。公开固定前缀必须有独立来源，不得允许任意目标 recover token 混入。

## 5. 运行状态与提交事务

最少运行状态：

| 状态 | 语义与生命周期 |
| --- | --- |
| `current_tokens` | 完整离散暂定序列；只有 <=committed_end 的位置已正式经过位置收尾 |
| `current_embedding` | R 使用的工作 embedding；R 前重新用 current_tokens 锚定已提交前缀；CP 接受仅同步 p 的真实 token embedding |
| `committed_end` | 初始 E-1，外层严格 +1，不因内层 rerank 前进或回退 |
| `candidate_table_by_position` | 最新被接受状态的表；每表带 prefix fingerprint、generation、原始排序与分数 |
| `future_context_dirty_from` | CP 改变前缀后，b+1 起未来暂定表需在正常提交前刷新；新的有效表覆盖时解除对应失效标记 |
| `processed_checkpoint_ids` | 保证严格不重叠且每段只收尾一次；段 ID 可直接由 (b-E+1)/5 推导 |
| `checkpoint_events` | 在线诊断与动作结果列表，方法返回后由主流程序列化 |
| 临时旧段快照 / 前缀 KV | 一次 checkpoint 或候选事务内使用，结束即丢弃 |

### 5.1 候选表更新规则

初始 rerank 的表建立初始代次。R 在 i 的候选试算只写暂存表；R 接受时再覆盖 i..T-1，拒绝时丢弃。表中 candidate ID 与 cosine 必须逐行对应，不能在筛选 ID 后沿用未同步索引的分数。

CP 接受之后，未来 p 的单点表分数可能因左前缀变化而过期。下一正常位置先用现有策略刷新当前位置的 embedding 候选、PPL 候选和单点 cosine；一旦刷新改变 token，后面的表继续保持失效。不得把预先得到的整条 ret_list 当成已经处理完的后续恢复。

同一段 checkpoint 前没有另一轮本段修复，段内 p 的表只要来自最近被接受状态且 prefix fingerprint 相符就可用于便宜筛选。发现表缺失或失配，应记录错误并保留原 token；不要到 rejected event 或其他版本结果里 fallback。

### 5.2 三类事务不得互相吞并

- **R 事务**：保持旧的连续 hidden-loss 接受与预算。它失败时不能丢掉此前 CP 已接受的前缀。
- **CP 事务**：固定其它离散 token，一次只允许提交 p；拒绝时不改正式状态。不计入 R attempt。
- **后续恢复**：只处理 b+1 以后的未提交位置。即使 CP 修复后仍低于 0.90，也不能再次调用本段 CP。

不得把 CP 放入 R 的大范围 try/except 中，以免 CP 失败被误记成 R 拒绝，或对已经接受的 R 做额外回滚。分段调度必须在 R 事务之外统一收尾。

## 6. Hidden / cache 适配的实施要求

1. 新版 exact-layer 提取明确 `output[0]`，hook 只挂指定 block，使用 try/finally 移除。返回 `[batch,position,hidden_dim]` tensor，不从混有 cache 的 collection 尾部取值。
2. 目标在采集边界冻结并 detach；模型 eval。新分支采集时显式关闭不必要 cache，检查与指定 block 的 direct output 对齐。不改变旧分支获取规则。
3. 当前观测只用离散 ID；默认单样本、无 padding。target 和 current 在相同绝对位置 slice；embedding 位置 i 的 hidden 对齐 target i，不是用于预测下一 token 的 logits i。
4. `forward_mode=cached_prefix`：在 p 前建立同模型离散前缀 KV，候选副本继续 p..b；完整 mask 长度和 position/cache 索引按安装的模型代码适配。无法支持的模型/cache 类型在前置检查中拒绝。
5. `forward_mode=full_prefix`：显式的验证或兼容配置，用当前 tokens[:b+1] 前向，返回 a..b hidden。不能在 cached 报错后静默启用。
6. 第一版候选顺序前向，候选数由原池界定，不强制实现可变 cache 的批量扩张；以后若加 batching，须先验证相同分数、选择和状态隔离。
7. CP 成功或失败后丢弃临时 cache。下一位置按修复后的 ID 建立上下文。若以后保留全程 KV，其失效起点必须不晚于被修改的 p，而不是只截到 b。
8. 验证模式比较 full/cached 两种完整执行结果、候选顺序、层 hidden 与 C；不只比较最终 loss。严格 > 没有 margin，浮点路径差异属于必须量化的风险。

当前 `forward_and_get_last_hidden_state` 没有 cache 参数、不会显式管理 inference_mode 或异常时 hook 清理；它是语义参考，不是可以无修改套上 cache 的实现。`requirements.txt` 不构成缓存可用性证据。

## 7. 配置方案

假设版本名最终为 v2.2.2，新字段统一使用 `suffix_v2_2_2_*`。旧 R 超参数复制到新版本配置并记录实际值；不复用旧 config 作为可变共享对象。

| 字段后缀 | 建议值/规则 | 性质 |
| --- | --- | --- |
| `checkpoint_enabled` | 显式 true/false | 消融开关 |
| `checkpoint_size` | 必须为 5 | 上位固定 |
| `checkpoint_trigger_cosine` | 必须为 0.90 | 上位固定 |
| `checkpoint_stride` | 必须为 5 | 上位固定，禁止重叠 |
| `checkpoint_tail_policy` | `skip_incomplete` | 上位固定 |
| `checkpoint_max_repairs` | 必须为 1 | 上位固定 |
| `checkpoint_recursive` | 必须为 false | 上位固定 |
| `checkpoint_diagnostic_tolerance` | eta；建议工程种子 0.01 | 待实验定标，运行前固定 |
| `checkpoint_candidate_min_cosine` | 有限数值 [-1,1]；未设置时失败 | 真正接口缺口的最小补齐，数值待定 |
| `checkpoint_candidate_threshold_source` | 非空来源说明 / 开发配置标识 | 追溯来源，不能标成 inherited_v221 |
| `checkpoint_forward_mode` | 显式 `cached_prefix` 或 `full_prefix` | 工程选择 |
| `checkpoint_numeric_norm_epsilon` | 1e-8 | cosine 数值有效性保护 |
| `checkpoint_score_dtype` | float32 | 同一路径旧值/候选值一致 |
| `checkpoint_schema_version` | 1 | JSONL 解析口径 |

不存在 classifier gate、GT gate、额外 improvement margin、重叠开关、多位置修复配置或递归次数调参。对于固定合同的不合法覆盖应报错，而不是静默纠正。

CP off 时，第二阶段沿用与旧 v2.2.1 相同的路径，不生成任何 CP 前向或修复；应通过相同 Stage-1 输入的旧/新 off 等价测试。R max_attempts=0 与 CP enabled 是独立含义：CP on 时仍需生成离散序列并执行提交/CP，不能复用旧 `_disabled_result` 提前退出整个方法。新 R 预算为零表示禁用 R 试算，不表示禁用 CP。

`advanced_methods.json` 当前默认选 v2.1.1；专用 v2.2.1 config 才覆盖 selector。新配置必须显式写新 selector，不能只设置一个 enabled 字段。canonical selector 为 `suffix_version`，旧 `suffix_reoptimization_version` 仅兼容别名，冲突时继续报错。

## 8. 输出与日志合同

### 8.1 resolved_config.json

按新版本写入 `advanced_methods` 中被选择的版本项，避免被现有 selected-key 筛选丢掉。记录上述全部 CP 配置、R 配置、原始候选 K、filter_nonascii 实参、目标 block ID、公开前缀/位置协议、缓存模式及实际运行时模型/库信息。

`formal_gt_blind=true` 和 `gt_accessed=false` 只是声明字段，必须由测试和调用审计支持，不能用声明替代证据。

### 8.2 reconstructions.jsonl

推荐 canonical 字段 `suffix_reoptimization_v2_2_2_result`；保留现有通用结果引用供主流程选择，但不复制混淆旧版本键。完整两阶段入口采用 `stage1` 与 `reoptimization` 分组；`reoptimization.checkpoint` 中放摘要与事件。阶段 accuracy 仅在方法返回后附加。

每个完整段恰好一条终态事件，建议字段：

| 组 | 字段 |
| --- | --- |
| 身份与位置 | `checkpoint_id,a,b,eval_start_pos,position_index_base=0,target_block_index` |
| 观测 | `group_cosine_before,triggered,cumulative_cosine[5],deltas[5],diagnostic_tolerance` |
| 定位 | `diagnosis_type,selected_position,drop_baseline,recovery_position,followup_count,reason` |
| 候选来源 | `candidate_generation,prefix_fingerprint,candidate_token_ids,candidate_hidden_cosine,threshold,threshold_source` |
| 筛选与复查 | `eligible_ids,excluded_reasons,duplicate_mapping,candidate_group_cosine,invalid_candidate_reasons` |
| 结果 | `old_token_id,new_token_id,best_group_cosine,group_cosine_after,accepted,repair_attempt_count` |
| 成本 | `forward_mode,forward_calls,forward_token_count,cache_prefix_length,elapsed_ms` |
| 连续性 | `committed_end_before,committed_end_after,future_context_invalidated_from` |

未触发时累计轨迹及后续字段可为 null/空；不必为了填字段额外前向。尾段只在样本级记录 `tail_skipped_count`，不伪造完整 checkpoint。数值不可用写 null 和原因，禁止 NaN/Inf 序列化为非标准 JSON。

`repair_attempt_count` 指一次定位后的候选复查事务（0 或 1），不是候选 forward 数；候选数另计。`group_cosine_after` 在拒绝时等于旧值；不能填未提交候选的最高分。终态原因至少覆盖 passed、no_localizable_drop、missing_or_stale_candidate_table、no_eligible_alternative、nonfinite_observation、candidate_forward_failed、no_improvement、accepted。

不得将 GT ID、correct/incorrect 标签、accuracy 塞入在线候选表。离线匹配放在单独后处理区域，不能再反馈到 scorer、排序或回滚。

### 8.3 experiment.log 与 artifact

维持主流程 `write_experiment_sample_summary` / `write_experiment_average_summary` 的固定摘要结构，只映射新版本最终阶段结果。新 CP 指标、时延、触发点一律不写 experiment.log。仍以 timestamp 目录里的 resolved config、log、JSONL 为实验产物，不生成或更新 Excel。

CP 插在恢复中间，因此“CP 前 accuracy”没有天然等价的完整反事实序列；不能把 R 前的 pre_tokens 准确率命名为 CP-off 准确率。CP-off 效果需要独立同条件运行。若启用 CGMR，保留 suffix-final 快照供离线分析，CGMR 必须接收修复后的 final_tokens，不能再从旧 embedding 反演覆盖它们。

## 9. 必需测试与验证矩阵

本节为未来执行清单，本轮未运行这些测试。旧测试已只读检查：现有 v2.2.1 测试含配置、GT-free 签名、锚定、R 接受/拒绝与预算；使用的 4-token fixture 不足以覆盖本方法。

| 测试组 | 必须覆盖的行为 |
| --- | --- |
| 分段 | E=0/E=1、恢复长度 0/1/4/5/6/9/10/11；完整段数 floor(N/5)，不重叠，尾段不触发 |
| 调度 | R 未触发、预算耗尽、接受、拒绝、异常五种分支均推进游标并到达 CP；内层全后缀 rerank 不触发 CP |
| R=0 | CP on 仍正常离散恢复和执行 CP；CP off 与原路径一致 |
| 观测 | 离散 token 前向与连续 embedding 前向故意设置不同，确保选择离散结果；C[b] 等于段 C；不将 mean cosine 误当 sum cosine |
| 层与位置 | exact block output 和目标一致；tuple 含其他项时不误取；block 24 不是 collection[24] 的无条件别名；无 next-token shift |
| 前缀与 mask | 公开 BOS/无 BOS、E=0，错误固定前缀长度和不支持 mask 显式拒绝；不自动插入另一个特殊 token |
| 触发边界 | C=0.90 通过；略小触发；无舍入比较；零范数/非有限明确退出 |
| 诊断 | 孤立恢复 1/2 步、持续低位、继续下降、第三步才恢复、多个孤立下降、多个持续下降、先孤立后持续、并列选择 |
| 无定位 | 段首已低平坦、每步缓慢变差、末点无后效；不强选段首/末点，不跨段 |
| 表有效性 | 初始/已接受 R/已拒绝 R 表区分；prefix fingerprint 失配；前缀修改后未来表刷新；重复行 ID/score 对齐 |
| 便宜筛选 | 阈值缺失失败；等于下限入选；无合格替代项直接退出；special/非 ASCII 过滤不改变原表顺序或原 token 保留权 |
| 因果重算 | 使用带前缀依赖的小模型；只变 p ID，但 p+1..b hidden 确实改变；p 前 hidden 一致；候选不能复用旧下游 hidden |
| 独立候选事务 | 交换候选评估顺序（无并列）结果相同；旧 token/工作 embedding/基础 KV 不受试算污染；拒绝保持完整状态 |
| 接受 | 0.72→0.86 接受；相等拒绝；极小严格改善按合同接受；最佳候选位于原顺序后部仍应被评估；并列按原表顺序 |
| 修复上限 | 一个 checkpoint 至多一次事务、至多一个 ID 改变；接受后仍 <0.90 也不重新诊断；拒绝不换第二位置 |
| 后续连续性 | CP 修复后即使 R 预算耗尽，b+1 的 PPL/单点 scorer 也读新前缀；下一个 R 拒绝不能撤销此前 CP |
| 缓存 | empty prefix、独立 clone、位置/attention mask、cached/full 同输入逐候选等价；cache 失败无静默 fallback，hooks 异常后清除 |
| 版本与日志 | 旧 selector 保留，新版本 resolved 项不被过滤；不新增 experiment.log 明细；JSONL 标准可解析、无 NaN；不生成 xlsx |

### 9.1 GT-blind 检查必须同时有静态与动态证据

- 静态检查公共签名、调用参数、import、闭包捕获，禁止把主流程总 record 或 GT 变量传进在线对象；候选合法性只由 tokenizer 和公开配置决定。
- 动态测试固定 target hidden、模型和公开前缀，只替换离线 GT 标签/accuracy 对象，online token 结果、触发、定位、候选排序、接受保持一致。用访问即报错的 sentinel 检查不读取，不是重新生成另一目标 hidden 后要求结果相同。
- scorer 与提交器可以在没有任何 GT 数据对象的环境下完成合成测试。
- 离线评估必须在方法返回之后执行；CGMR 若开启也不能消费离线字段。测试 hidden 提升但真实 token 更差的构造案例，在线仍按 hidden 合同接受，离线如实报告。

先新纯函数/因果小模型单测，再新旧路径回归和 config/log 集成测试，最后按授权在真实模型验证 cache、层索引和成本。最小编译检查包含新 sidecar、入口和输出改动；`py_compile` 缓存及测试临时产物放 `outputs/` 的任务专属子目录并清理。

## 10. 推荐实施顺序与完成判据

1. **核对规范与冻结配置**：重新检查 live 文件、版本号和目标运行环境，明确候选下限来源、eta、forward 模式；冻结本次 R 基线，不执行其他部件待做。
2. **建立版本骨架与 Stage-1 等价入口**：保留旧 selector；先验证新 CP-off 的 Stage-1 与 R 行为等价，再写 CP 功能。
3. **完成 exact-layer 和位置契约**：目标与离散前向对齐，先解决 tuple、mask、前缀边界问题。
4. **实现提交游标与有效候选表**：覆盖所有 R 分支；先验证每段只到达一次，试算表不污染正式表。
5. **实现纯诊断和筛选**：按最终设计处理证据不足与数值不可用，不补未知位置，不隐式放宽阈值。
6. **实现单候选重新前向与原子提交**：先显式 full_prefix 参考路径，再完成 cached_prefix 并验证一致性；保证后续恢复刷新只针对未提交位置。
7. **接入配置/JSONL/GT-blind 检查**：确认固定日志格式和版本隔离；完成合成测试与旧路径回归。
8. **等待另行授权的真实模型验证与实验**：先层/cache smoke，再独立 CP off/on 对照。复用原候选策略与 R 设置，单列未来表刷新成本；阈值开发数据与最终报告数据分开。

工程完成判据是接口、状态、边界和测试成立；方法效果仍必须由实验回答。即使编译和合成测试通过，也不能写成 checkpoint 已提升真实恢复率。
