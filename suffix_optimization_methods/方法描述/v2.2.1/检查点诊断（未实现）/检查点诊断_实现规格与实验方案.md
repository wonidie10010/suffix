## 1. 本轮确定的合同及文档优先关系

本组件在左到右恢复过程中，对已经完成的 5-token 离散段进行诊断；必要时复查一个历史位置的原候选，并提交至多一次单点替换。虽然沿用“检查点诊断”名称，正式启用组包含主动修复，不是早期只读观测组件，也不是模型的 gradient checkpointing。

| 项目 | 本版确定值或行为 | 来源 |
| --- | --- | --- |
| 分段 | 公开固定前缀之后，5-token 严格不重叠；不足 5 个的尾段跳过 | 沿用现有最终设计 |
| 段级触发 | 原始 hidden 向量求和后的 cosine 严格小于 0.90 | 沿用现有最终设计 |
| 候选质量下限 | 候选单点 hidden cosine **大于等于 0.90** | 用户 Q1 指定 |
| 诊断容忍量 | **eta=0.05**，同时用于明显下降与恢复判断 | 用户 Q4 指定，替代旧建议 0.01 |
| 前向方式 | **只实现 full_prefix**；顺序评估候选，不实现 KV 缓存 | 用户 Q2 指定，替代旧缓存优先路线 |
| 候选失败 | 任一合格替代候选前向失败，整次 CP 不提交；候选新分数非有限/不可定义同样处理 | 用户 Q3 接受整体保留策略；数值失败按同一事务原则落实 |
| 定位 | 优先 earliest sustained drop；否则选下降最大的孤立异常；并列选更早位置 | 沿用现有最终设计 |
| 接受 | 所有合格替代候选成功评分后，最佳新段级 cosine 严格大于旧值 | 沿用现有最终设计 |
| 修复上限 | 每个完整段至多一个位置、一次候选复查事务；不递归 | 沿用现有最终设计 |
| 实验组 | **CP-off 与 CP-on 两组**，不设置“只诊断、不提交替换”实验组 | 用户 Q5 指定 |
| 在线信息 | 允许目标 hidden；禁止 GT token、accuracy、oracle 参与任何在线决策 | 沿用现有最终设计 |

两个 0.90 分别控制段级触发与候选筛选，必须使用独立字段，不能共用一个配置变量。它们数值相同不表示语义相同。候选下限与 eta 是用户指定值，未经过本轮实验定标，不描述为最优阈值。

## 3. 输入、层与位置协议

在线入口仅接收模型、tokenizer、工作 embedding、detached 目标 hidden、公开前缀、mask、层元数据和配置。不得接收 GT ID、accuracy 对象、整条离线样本 record，或捕获这些对象的闭包。

1. 首版支持同一 Qwen2/Qwen2.5 causal LM、相同权重及 adapter 状态、batch=1、全有效且无 padding 的序列。不支持的模型、内部 mask 空洞或形状在模型计算前显式拒绝。
2. `target_block_index` 是从 0 开始的 Transformer block 索引。配置 24 指 `model.layers.24` 的输出，不无条件等于 hidden collection 的第 24 项。
3. 新版统一 exact-layer 提取：block 输出是 tuple 时取 `output[0]`，否则取输出 tensor；用 `try/finally` 移除 hooks，验证 `[1,T,D]`。目标与当前必须来自同一 block 输出位置，不混用最终归一化后的表示。
4. 目标采集位于方法边界之外，采集后 detach；真实输入仅用于构造目标观测。在线修复器不得继续取得生成该观测的私有 token ID。
5. 公开前缀长度记作 `E=eval_start_pos`，必须有公开来源，例如固定 BOS；不能把未知目标首词作为固定前缀传入。禁止因版本名变化自动插入新的 BOS/EOS。
6. 所有位置为 0-based 绝对 token 索引，目标 hidden 的位置 p 与当前 hidden 的 p 对齐，无 next-token 偏移。

完整序列长度 T，第 g 段（g 从 0 起）：

```text
a = E + 5*g
b = a + 4
仅 b < T 时执行 checkpoint
段 hidden = hidden[:, a:b+1, :]
完整段数 = floor((T-E)/5)
尾段 token 数 = (T-E) mod 5
```

例如 E=1，首段绝对位置为 `[1,5]`，下一段 `[6,10]`。T=E 时无可恢复位置，直接产生合法空结果；不要为零长度创建 checkpoint。

## 4. 提交调度与状态

最小运行状态如下，不建立复杂的全局搜索框架。

| 状态 | 约束 |
| --- | --- |
| `current_tokens` | 完整暂定序列；只有到 `committed_end` 的位置已经完成外层处理 |
| `current_embedding` | R 使用的工作表示；CP 接受只同步被替换位置的真实 token embedding |
| `committed_end` | 初值 E-1；每个外层位置收尾加 1，内层 rerank 不得推进 |
| `candidate_table_by_position` | 被接受状态的原始行顺序、ID、分数、selected ID、前缀指纹及生成代次 |
| `dirty_positions` | 前缀改变后尚未刷新、尚未提交的未来位置；可用等价区间结构实现 |
| `processed_checkpoint_ids` | 防止重复执行；每完整段恰好一条终态事件 |
| `checkpoint_events` | 在线字段；方法返回后交主流程落盘 |

主流程伪代码：

```text
validate_contract()
生成初始完整离散序列与有效候选表
committed_end = E - 1
for i in [E, T):
    如 i 的候选上下文失效：按原策略刷新当前位置及候选表
    以当前离散 token 重建已提交锚定前缀
    执行原 R 触发、预算、试算、接受/拒绝事务
    接受 R：更新工作 embedding、token 和被接受的后缀候选表
    拒绝 R：丢弃试算表与试算状态
    finish_position(i):
        committed_end = i
        if CP_enabled and (i-E+1) % 5 == 0:
            执行 [i-4, i] 的一次 checkpoint
返回最终 token、embedding、R 事件、CP 事件
```

未触发 R、预算耗尽、R 接受、R 拒绝、可恢复 R trial 失败，均必须到达 `finish_position`。CP 不放进 R 的 try/except，CP 失败不能撤销此前已经接受的 R。

CP 接受后，不重新执行已完成段。`b+1` 及之后的暂定表失效，逐位置正常继续恢复时刷新；R 接受产生的新表若前缀一致，可清除相应失效标记。刷新一个未来 token 后，其下游旧表仍需检查有效性。不能因为 R 已无预算就直接沿用修复前的未来序列。

R=0 的新版语义：R 试算禁用，但初始离散恢复、位置收尾及 CP 仍可执行。对应新版 CP-off 也执行相同初始离散恢复，便于构造有效对照。旧 v2.2.1 的 R=0 disabled 返回没有完整 final_tokens，不能直接充当该对照。

## 5. 段级观测与数值规则

模型处于 eval。CP 观测使用 `no_grad` 或等价局部无梯度上下文，不把整个含 R 的方法包进 inference_mode。适配器显式 `use_cache=False`，每次从位置 0 到 b 完整前向：

```text
input_ids = current_tokens[:b+1]
mask = 对应前缀的全有效 mask
h = exact_block_output(input_ids)
u = sum(float32(h[i]), i=a..b)
v = sum(float32(target_hidden[i]), i=a..b)
C_old = dot(u,v) / (norm(u)*norm(v))
```

不得用连续 embedding 前向、不同历史时刻的 hidden 拼接、逐 token 单位化或逐点 cosine 均值替代本指标。

向量及分数需有限；任一向量范数 `<=1e-8` 时记为不可用，保留状态并结束该 CP。该常数仅定义数值有效域，不是接受 margin。比较使用未舍入值，不将不可用值填成 0，不通过增加 epsilon 将零向量制造成可用分数。

`C_old >=0.90` 时不触发；`C_old <0.90` 时复用本次五个 hidden 计算累计轨迹。CP-off 不进行这些额外前向。

## 6. eta=0.05 的可执行诊断规则

对同一段观测计算：

```text
C[k] = cosine(sum(h[i], i=a..k), sum(target[i], i=a..k))
Delta[a] = null
Delta[k] = C[k] - C[k-1], k=a+1..b
明显下降：Delta[k] < -0.05
下降前水平：B = C[k-1]
恢复：后续 C[j] >= B-0.05
```

必须有 `C[b]=C_old`。任一需要的累计值不可定义时，整段记 `invalid_cumulative_observation`，不利用残余轨迹强行定位。段首没有段内前一步，不能人为设 C[a-1]=1。

对每个明显下降点 k 独立分类：

| 条件 | 分类 |
| --- | --- |
| 在 k+1 或 k+2 首次恢复，且位置不越过 b | 孤立异常候选 |
| 至少有一个后续位置，且直到 b 都没有恢复 | 持续恶化候选 |
| 第三个或更晚后续位置才恢复 | 恢复过晚，证据不足，不作为修复位置 |
| k=b，没有后续位置 | 右端证据不足，不当作持续恶化 |

定位优先级：先选持续恶化候选中最早的 k；若没有，再选孤立异常候选中下降幅度最大的 k，完全并列选较早位置；两类均无则不修复。持续恶化允许只有一个后效样本，但记录 `followup_count`，不把这一弱证据写成确定错误源。

以下为规则示例，非真实实验轨迹，全部最终值低于 0.90：

| 五点累计 cosine | 按本版规则的结论 |
| --- | --- |
| 0.98, 0.86, 0.96, 0.82, 0.81 | 第二点孤立且已恢复；第四点持续下降，优先选第四点 |
| 0.88, 0.76, 0.87, 0.87, 0.86 | 第二点孤立下降后恢复，选第二点 |
| 0.98, 0.95, 0.92, 0.89, 0.80 | 仅末点明显下降但无后效，不定位 |
| 0.85, 0.85, 0.85, 0.85, 0.85 | 段已低但无明显下降，不定位 |
| 0.97, 0.84, 0.86, 0.88, 0.89 | 第二点直到段末未达恢复线 0.92，选第二点 |

eta 从旧建议 0.01 增至 0.05，同时使明显下降更难成立、恢复更容易成立；可能降低可定位比例，应在实验中报告。不要为增加触发或修复数量临时放宽 eta。精确等号边界用可精确表示的输入构造单测，不依赖显示小数相减的偶然舍入。

## 7. 候选表生命周期与 0.90 筛选

CP 只能复用定位位置 p 的当前有效表，不生成新候选源。候选表来自初始 rerank、已接受 R，或 CP 后未来位置的正常刷新。拒绝 R 的表永不进入正式索引。

每表记录 `position`、`generation`、`prefix_fingerprint`、原始候选 ID/分数行及所选 ID。前缀指纹基于完整 `tokens[:p]` 的确定性编码与稳定摘要，不能用跨进程不稳定的 Python hash。代次用于追踪来源；有效性必须实际检查前缀，而非仅比较一个全局计数。

筛选顺序：

1. 检查表存在、行 ID 与分数对齐、前缀一致；失败则本段不修复。
2. 按原顺序检查 ID 范围、special token 和 `filter_nonascii`。合法性使用公开 tokenizer 规则，不接触 GT。不改变原始 R 的过滤行为。
3. 保留有限且单点 cosine **>=0.90** 的候选；原表非有限分数在此淘汰并记录原因。
4. 当前 token 始终可作为保留结果，不要求自身达到 0.90；从替代候选前向列表中排除它。
5. 重复 ID 按首次出现顺序去重，仅评分一次，保留原始行到唯一候选的映射。重复 ID 分数若出现不一致，记录原始分数及是否至少有一行合格，不能错位拼接 ID 与分数。

无合格替代项：`no_eligible_alternative`，直接结束本段。不降低下限、不换位置、不追加 Top-N 搜索或 CGMR 候选。

原策略为 embedding Top-K 后追加 PPL Top-K，默认 10+10，PPL 只在 p>0 且启用时追加；候选自然有界。原单点分数只用于便宜筛选，不能代替新段级评分。

## 8. Full-prefix 候选试算与原子提交

冻结进入 CP 时的 token、工作 embedding、有效表、游标与旧段分数。每个合格唯一替代 ID v 从同一快照开始：

```text
trial_tokens = old_tokens[:b+1] 的独立副本
trial_tokens[p] = v
trial_hidden = exact_block_output(trial_tokens, use_cache=False)
C_v = cosine(sum(float32(trial_hidden[a:b+1])), target_segment_sum)
```

每个候选均完整前向 `[0,b]`，重新取整个 `[a,b]` 段 hidden，不拼接旧下游 hidden。除 p 外全部 token ID 固定；p+1..b 的 hidden 随上下文自然改变。段后未来 token 不参与评分。旧段与候选必须使用同一 batch 大小、dtype、设备、attention 实现及前向模式。

### 8.1 失败边界

- 筛选前旧表分数非有限：按第 7 节排除该行，尚未进入候选复查事务。
- 合格候选进入试算后，任一前向异常、新分数非有限或范数不可定义：终止剩余试算，**整个 CP 不提交**。已经算出的最好候选也不得提交；记录未评估 ID 和失败原因。
- 旧段或累计观测无效：不进入候选试算，保留状态。
- 可恢复的局部评分失败：清理 hooks/临时 tensor，保留已接受 R，CP 记完成，继续下一个外层位置。
- CUDA 上下文损坏、无法恢复的 OOM、契约违规等使后续执行不可信的错误：仍不得提交 CP，但停止该样本/运行并标记失败，不能以宽泛 catch 伪装正常完成。用户取消信号继续向上传播。

“整体保留”指保留进入 CP 时的正式状态，不是回滚整个样本或之前的 R/CP。检查点不自动重试、不切换实现、不改候选池。

### 8.2 全部成功后的提交

所有合格候选成功评分后，按 C_v 最大选优，完全并列按原表首次出现顺序。仅当 `best_C > C_old` 时提交。

接受：只修改 p 的 token ID 与该位置工作 embedding，更新文本，将 b+1 后的受影响候选表标记失效。已提交的 p+1..b ID 保持不变。下一个 R 必须从修复后的离散 token 构造锚定前缀。

拒绝：token、embedding、有效表不变；`group_cosine_after=C_old`。接受后不必达到 0.90；不增加 improvement margin、单点不恶化约束或 R loss 二次门控。即使仍低于 0.90，本段也结束。

## 9. 配置与版本接入

### 10.2 每段事件

CP-on 每个完整段恰好一条终态事件；CP-off 的 CP 事件为空。建议字段：

| 分组 | 字段 |
| --- | --- |
| 身份 | `checkpoint_id,a,b,eval_start_pos,position_index_base,target_block_index` |
| 观测 | `group_cosine_before,triggered,cumulative_cosine,deltas,eta` |
| 定位 | `diagnosis_type,selected_position,drop_baseline,recovery_position,followup_count` |
| 候选来源 | `candidate_generation,prefix_fingerprint,original_candidate_ids,original_candidate_scores` |
| 筛选 | `candidate_min_cosine,eligible_ids,excluded_reasons,duplicate_mapping` |
| 评分 | `evaluated_ids,candidate_group_cosines,failed_id,unevaluated_ids,all_candidates_scored` |
| 结果 | `old_token_id,new_token_id,best_group_cosine,group_cosine_after,accepted,reason,repair_attempt_count` |
| 调度 | `committed_end_before,committed_end_after,future_context_invalidated_from` |
| 成本 | `forward_mode,observation_forward_calls,candidate_forward_calls,forward_token_count,elapsed_ms` |

未到达的字段为 null/空，不为了填字段额外前向。标准 JSON 禁止 NaN/Inf；不可用数值写 null 加原因。失败候选前已经计算的最大值可以单列为 `partial_best_group_cosine`，不得放进代表完整选优的 best 字段。

样本摘要记录完整段数、触发数、定位数、启动复查数、接受数、数值/前向失败数、尾段跳过 token 数及未来表刷新成本。非致命完整运行的终态数应等于 `floor((T-E)/5)`；不同终态计数之和应等于事件总数。

## 12. 两组配对实验方案

### 12.1 实验问题与分组

核心问题：在同一 Stage-1 起点和相同 R/候选机制下，加入固定规则 CP 后，最终 token 恢复效果是否改善，代价是多少，是否出现 hidden 改善而 token 改坏。

| 组 | 配置 | 作用 |
| --- | --- | --- |
| CP-off | 新版入口，R 保持原设置，checkpoint_enabled=false | 恢复效果与成本基线 |
| CP-on | 同新版入口与 R 设置，checkpoint_enabled=true | 完整诊断、候选复查与单点修复 |

不设置只诊断组，不把某次 on 运行的中途快照冒充 off。两组分支之后 R 轨迹或未来 token 可能自然不同，这是 CP 总体作用的一部分。

### 12.2 首轮规模与固定条件

首轮沿用当前 `experiment_configs/l24_deml3x4.json` 的小样本范围：Skytrax、CMS、ECHR_Law 各 4 条，合计 12 条；模型 `Qwen/Qwen2.5-1.5B`，block=24，seed=0，CGMR=none，embedding/PPL K 各 10。Stage-1 配置按实际 include 合并结果冻结；目前基础文件为 lr=0.1、epoch=1000、alpha=0.001、clip=true、uniform 初始化 0.1、cosine 优化/离散评分。

这只是首轮配对验证范围，不预先宣称统计充分。实际读取样本的稳定 ID、顺序、tokenizer revision、截断/预处理及有效恢复长度在运行前写入 manifest；不能只靠“各 4 条”推断两组相同。未满 5-token 的样本仍保留并报告零完整段，不能为了获得收益而事后换样本。

每条样本 Stage-1 只生成一份快照，包含工作 embedding、detached target hidden、mask、E、公开前缀及随机状态；两组从独立副本恢复。模型权重/模式不变，记录快照校验值。GT 保存在离线评估侧，不打包进在线快照。Stage-1 共享成本单列，既报告第二阶段成本，也报告计入同一 Stage-1 成本的端到端成本。

旧版回归是工程检查；正式两组均走新版入口，避免入口/层采集差异混入 CP 比较。若无法证明 Stage-1 快照与原行为一致，先停止并定位，不继续解释修复效果。

### 12.3 离线评估定义

所有在线步骤结束后再读取 GT，恢复区间为 `[E,T)`，两组对齐相同样本和位置。保留原有准确率口径，并明确新增统计的分母：

| 指标 | 定义 |
| --- | --- |
| 样本 accuracy | 恢复区间正确 ID 数 / 有效恢复 token 数；长度为 0 列为不适用并单列数量 |
| 宏平均 accuracy | 有效样本 accuracy 的均值；分别报告各数据集及总体 |
| 微平均 accuracy | 所有正确 token 总数 / 所有有效恢复 token 总数 |
| 配对增量 | 每样本 on-off；报告改善/持平/下降样本数及每数据集增量 |
| 最终修好数 | 最终 off 错、on 对的位置数 |
| 最终改坏数 | 最终 off 对、on 错的位置数 |
| 直接替换得失 | 对每个接受事件的 p，用该事件 old/new ID 离线判定错→对、对→错、错→错；与最终全序列差异分开 |
| 触发率 | 触发段数 / 完整段数 |
| 可定位率 | 定位成功段数 / 触发段数 |
| 候选不足率 | 无合格替代项的段数 / 定位成功且表有效段数 |
| 接受率 | 接受段数 / 启动候选复查事务数；另报失败事务数 |
| hidden 与 token 不一致 | 已接受且 cosine 改善、但替换位置由对变错的数量与比例 |

零分母标注“不适用”，不填成 0 掩盖覆盖不足。最终修好/改坏包含未来恢复路径的变化，不全部归为直接 CP 替换；直接替换得失是局部事件口径。

通过 on 组已记录的段分数与该段在检查时的 token，可离线分析触发段是否富集错误。若保存检查前段 ID，应只保存算法自己的预测 ID；GT 后附加在隔离评估区域。阈值诊断指标来自 on 轨迹，受先前修复影响，不称为 off 轨迹上的无偏诊断能力；本版不为此补第三实验组。

### 12.4 成本与停止条件

记录第二阶段/端到端时间、峰值显存、CP 观测与候选 forward 数、处理 token 数、未来表刷新时间及 JSONL 字节。GPU 计时在阶段边界同步，两组相同热身；交替两组执行顺序并记录，避免总让一组承担首次加载。单次 12 样本时间只作为初步测量。

首版顺序 full-prefix：正常一个完整段需要 1 次旧段观测；若有 K 个唯一合格替代项，额外最多 K 次候选前向，每次长度 b+1。该段 CP token 处理上界为 `(1+K)*(b+1)`，不含未来表刷新和 R。K 不超过原候选池行数（默认最多 20，去除当前 ID、重复及过滤项后通常更少）。失败可提前停止，但不能少评候选后提交。

短单测、层协议 smoke、两组输入一致性和旧版回归任一失败，停止正式配对实验。运行中出现系统致命错误停止该次运行；局部 CP 评分失败按事务策略记录，必须报告失败率，不能从报告中悄悄删除。

完成首轮两组后停止，不自动扫描阈值、扩大样本、增加 seed 或修改方法。没有完整段、没有触发、没有合格候选或没有接受时，如实报告相应机制未得到充分覆盖；不能为了让方法“有效”临时改 0.90/0.05。

## 13. 如何判定完成与解释结果

**当前实施交付完成**要求新版隔离、明确配置、正确调度与事务、适用的纯函数/合成小模型/集成/旧路径回归测试通过，一键程序、内部 runner 与两组配置完整，编译及无模型 dry-run 通过。交付时明确标注“已实施；真实模型验证与完整实验待后续指令”，并逐项报告实际验证范围，不以尚未执行真实实验为由继续自动运行。

**后续真实环境验证完成**要求部署后的真实目标层、位置、快照复用与前向行为通过 smoke，真实 artifact 可追溯。这一阶段与实施完成分开；合成测试或编译通过不能替代真实模型验证。

**首轮实验完成**要求两组配对样本、快照和配置核对一致，三类 artifact 完整，逐样本及总体效果/成本/失败均已报告；出现缺失或失败样本要单列，不能悄悄更换样本后仍称原配对完整。

**方法效果**不预设成功：可报告“这 12 条样本的配对恢复率提高/持平/下降”，不得扩展成总体显著提升。若 hidden 提高但 token 恢复不改善，先按复查清单分析触发覆盖、定位、候选不足与改坏案例；不得增加在线 GT gate。候选下限 0.90 导致大量无替代候选也是有效发现。

后续是否做大规模实验、缓存加速、阈值修改或新方法版本，由首轮证据和新的用户指令决定。本版不实现这些扩展。

入口至少支持 `--python`、`--runtime`、`--result-root`、`--model-path`；Python 选择顺序沿用显式参数 → `DEML_SUFFIX_PYTHON` → 当前解释器。模型路径使用显式参数 → `DEML_MODEL_PATH` → 项目既定缓存解析规则，不能把当前 Windows 或历史服务器绝对路径写死为唯一位置。运行模式下找不到本地模型/数据时明确失败，不隐式下载。

项目根通过脚本自身路径计算，不能依赖用户启动时的工作目录；用参数列表调用子进程，正确处理中文与空格路径。沿用现有 GPU/共享 runtime 配置约定，记录实际解析结果。

`--dry-run` 检查入口/runner/配置存在性、配置 include 与 selector、两组差异白名单、固定 CP 合同及拟使用的模型/数据路径，打印预定组别、输出位置与执行步骤。它不导入会初始化模型的执行路径、不创建 GPU 上下文、不生成 Stage-1 快照、不调用实验子进程、不写正式 artifact。本地缺少服务器模型/数据时列出“服务器运行前待验证”，与配置/布局错误区分；dry-run 通过仅表示实施布局与计划检查通过，不表示服务器就绪。

### 14.3 配对执行不能退化为两个独立初始化的 subprocess

runner 必须使用第 12 节的共享 Stage-1 快照合同：每个样本只产生一次 Stage-1 输出，两组分别接收独立副本并恢复相同随机状态。可以通过新版两阶段入口与快照输入/输出接口编排，但不能只是连续运行两个原始 `invert.py --config`，让它们各自重新初始化 Stage-1 后声称“同一起点”。

配置与 manifest 记录 `pair_id`、样本顺序、快照校验值、两组有效配置校验值及各自真实 timestamp run 路径。完整快照若需要持久化，只包含在线允许的张量与公开元数据，不包含 GT ID；临时快照放任务专属 `outputs/` 并在消费后清理，manifest 保留校验与配对证据。

正式 runner 只编排 CP-off 与 CP-on，不加入只诊断组，不沿用旧版 frozen baseline/baseline+R 标签。两组可交替执行顺序，但标签及配对关系固定。某组异常退出或 artifact 不完整时停止该配对流程并返回非零码，标记 bundle 未完成，不自动补跑、不跳过后谎称两组成功。

smoke 同样覆盖 off/on 配对链路，使用至少包含一个完整 5-token 恢复段的短输入；缩小 Stage-1/R 步数时将有效参数和 `run_kind=smoke` 写入记录，不混入正式 12 样本结果。真实 smoke 未触发修复不能证明修复分支已实测，分支覆盖仍需合成测试支持。

### 14.4 结果、日志与验收

默认 bundle 索引目录建议为 `实验/结果/suffix_v2.2.2_bundle/<bundle_timestamp>/`，与旧版本隔离。这里存运行 manifest、有效配置、编排日志和离线配对汇总；三类正式 artifact 仍以主流程写入的 `results/invert_timestamp_runs/<method_version>/<timestamp>/` 为准，通过 manifest 指向真实路径，不能根据 output_dir 或猜测文件夹名称认定结果。

runner 编排日志单独写 `runner.log`；不得向固定 `experiment.log` 插入 CP 明细或部署日志。两组都校验 selector、CP 开关、0.90/0.05、full_prefix、CGMR=none、样本 ID/数量、Stage-1 快照一致性和标准 JSON 可解析性。不生成 Excel，不覆盖历史 bundle。

当前实施验收必须用 mock/subprocess stub 和小型 fixture 证明：入口转发参数与退出码正确；任意 cwd 可定位项目；缺失配置明确报错；两组参数无意外差异；共享快照真正传给两组；失败不会继续伪造完成；dry-run 不调用模型与实验执行；import/--help 无运行副作用。测试生成文件仅放本任务的 `outputs/` 子目录，完成后清理。

无参数会启动正式实验，因此当前实施验证**只能调用 dry-run、帮助和 mock 测试**，不能为验证“一键可用”直接运行无参数入口。实现一键程序不等于已获执行实验的指令。
