# 检查点诊断：实验后复查问题清单

> 用途：第一版实现并得到实验结果后，按本清单逐项复查方法是否值得保留、哪些假设成立、哪些地方需要修改。
> 原则：先判断核心机制是否提供真实增量，再讨论阈值、段长或候选扩展。不要因为结果不理想就立即堆叠新模块。

## A. 最核心：段级和向量 cosine 是否真的有诊断价值

1. 5-token 段的 `C_S = cos(Σh_i, Σh_i*)` 与该段离线 token 恢复质量是否存在稳定关系？
2. `C_S < 0.90` 是否确实富集了更容易出错/更值得修复的段？
3. 有多少错误段满足 `C_S >= 0.90` 而被漏过？这些漏检是否集中于某种模式？
4. 有多少高质量段满足 `C_S < 0.90` 而被误触发？额外计算是否可接受？
5. 相比简单的逐位置 cosine 均值/最小值，和向量 cosine 是否提供额外辨别力？如果没有，应重新评估本方法的核心必要性。

## B. 固定阈值 0.90 是否合理

1. 正常段与异常段的 `C_S` 分布实际重叠有多大？
2. 0.90 是否明显过松或过严？
3. 若调整阈值，是否能用开发/离线统计得到一个稳定常数，而不是按测试 accuracy 调参？
4. 不同数据集/样本长度/目标层是否需要不同阈值？若需要，是否会破坏第一版“固定常数”的简洁性？
## C. 段内累计轨迹是否真能定位传播形态

1. 触发段中，累计 cosine 轨迹是否经常呈现可解释的“单点波动”和“持续恶化”两类模式？
2. earliest sustained drop 是否比“最大下降点”“最大单点误差点”更能定位一个值得干预的位置？
3. 所谓累计恶化是否只是普通噪声叠加，还是确实能在多个位置持续体现？
4. “下降后恢复”的容忍范围该如何定义？是否存在一个简单稳定的规则？
5. 如果大多数触发段都无法稳定分类为孤立/累计两类，当前段内诊断定义是否需要简化或重构？

## D. 单点干预是否足够

1. 只处理孤立异常点或 earliest sustained drop，是否经常能改善整个 5-token 段的 `C_S`？
2. 改变初始点后，下游 hidden 是否出现一致改善，还是通常只改善该点自身？
3. 有多少案例表现为：候选本身更好，但固定后续离散 token 后无法体现收益？
4. 若上述案例很多，是否说明未来需要研究“起点改变后允许局部后续 token 重新适应”？
5. 若单点干预几乎无效，则不要直接增加多点联合搜索，先确认定位指标本身是否有效。
## E. 候选复查机制是否有效

1. 原候选表经过现有阈值筛选后，通常还剩多少候选进入 checkpoint 复查？
2. 更优 token 是否经常根本不在原候选池中？如果是，候选覆盖率可能比 checkpoint 评分本身更限制性能。
3. 用整段 `C_S^(v)` 重排候选，是否相较原单点评分产生有意义的排序变化？
4. 被 checkpoint 改选的候选，是否更常带来下游 hidden 改善？
5. “只要 `C_S^(new) > C_S^(old)` 就接受”是否出现大量极小幅度、无实际价值的修改？若出现，再讨论是否需要最小 improvement margin。

## F. 计算开销是否符合预期

1. 实际触发 checkpoint 的比例是多少？
2. 每个触发段平均有多少候选需要重新前向？
3. 是否正确复用了异常点之前的前缀/缓存，只重算到当前 checkpoint 末尾？
4. 候选能否安全批量 forward，以降低墙钟时间？
5. checkpoint 带来的总时间、显存和 forward 次数增量是多少？是否明显低于连续重优化类方法？
## G. 已知结构局限在实验中是否真的重要

1. 严格不重叠的 5-token 分段是否明显漏掉跨边界传播，例如前一段末尾影响下一段前几位？
2. hidden 和向量是否出现明显的误差抵消，导致局部问题被高段级 cosine 掩盖？
3. 5-token 段长是否过短或过长？只有当核心机制有效后，才值得比较 4/5/8 等长度。
4. 最后不足 5 个 token 不做 checkpoint 是否造成可观察的系统性缺口？
5. 单次修复上限是否足够，还是大量段在第一次修复后仍存在明显可修复问题？若要扩展，也应先保留严格次数上限。

## H. 解释边界与 GT-blind 审计

1. 在线触发、定位、候选筛选、候选排序、接受过程中是否完全没有读取真实 token 或 accuracy？
2. 目标 hidden state 的来源和位置对齐是否与当前 v2.2.1 语义一致？
3. 离线报告中是否把“hidden 改善”与“真实 token 恢复正确”明确分开？
4. 是否存在 hidden cosine 提升但 token accuracy 下降的补偿案例？比例有多大？
5. 若存在，应把它作为方法性质报告，而不是通过在线 accuracy gate 修补。

## I. 实验完成后的最终去留判断

优先回答一个总问题：在相同候选来源和有限额外 forward 预算下，checkpoint 是否比原有逐位置决策更容易发现并修复具有下游影响的历史选择？

若答案为否，应优先删除或简化 checkpoint，而不是继续叠加段落关系矩阵、复杂分类器、多点联合搜索或无限回放。

若答案为是，再按证据强弱依次考虑：阈值再标定、恢复容忍量、段长消融、跨边界问题、候选扩展、局部路径重新适应。
